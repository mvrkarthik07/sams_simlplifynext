## Design brief — follow exactly, do not substitute your own direction
Subject: an entitlement register for a security operator who reads it daily for long
stretches. Vernacular is ledgers and audit records, not a SOC neon wall.

Tokens — three layers per the design-system skill: primitive -> semantic -> component.
Define in `frontend/src/styles/tokens.css`. No raw hex in any component.

  --paper #FBFBFA / --paper-sunken #F2F3F1 / --ink #16181A / --ink-muted #5A6067
  --rule #E1E3E0 / --link #1B4DB1
  Tier: --tier-3 #B3261E, --tier-2 #B8620E, --tier-1 #1F6F4A, --tier-0 var(--ink-muted)

Rules:
- Colour appears only to communicate risk tier or interactivity. Nowhere else.
- Hairline rules are the structural device. Zero box-shadows. Max radius 2px.
- Type: Public Sans (UI) + IBM Plex Mono (identifiers only — ARNs, repo paths, scopes,
  plan hashes). Mono is banned for labels and chrome.
- `font-variant-numeric: tabular-nums` on all numeric and timestamp cells.
- Sentence case throughout. No ALL-CAPS labels, no eyebrow labels above values, no
  middle-dot meta strings, no arrows appended to button text.
- Table rows 40px, body 13px/1.4, section headings 15px semibold.

## Required changes
1. **Layout.** Metrics compress to one 44px summary rule. The findings table is the hero
   and occupies the fold. Remove the dead space below it — if fewer than a viewport of
   rows exist, the table grows, it does not float in a short card.
2. **Show every finding.** Render all findings the API returns, sorted by score
   descending. Add column sort on score, identity, system, stage. Client-side filter
   chips for tier and source. No pagination below 200 rows.
3. **Metric honesty.** Each metric shows the measured value and its PRD target, visually
   distinguished. Any metric with no measurement pipeline renders as "Target 95% ·
   not yet measured" — never as a bare figure implying a result. This is not negotiable;
   it is the difference between a spec and a claim.
4. **Determinism panel** (PRD §7 step 6). On the plan view: both plan hashes in mono, set
   large, with an explicit match/mismatch verdict, plus the differing `plan_id`s and the
   `evaluated_at` / `as_of` offset shown openly.
5. **Provenance.** Live-capture vs simulated badge on every row and detail view, legend in
   the table header. Badges are text with a rule, not filled pills.
6. **States.** Skeletons that match final row dimensions exactly (zero layout shift).
   Empty state that names the next action. Error state showing the envelope `code` and
   `message` with a retry control.
7. **Dead ends.** Inventory every interactive element; anything that no-ops goes behind a
   build flag defaulting off. Write the inventory to `backend/artifacts/ui-inventory.md`
   as element / verdict / action.

## React performance rules
- No `useEffect` for derived state; compute during render.
- Memoize row components; stable keys from `finding_id`, never array index.
- Sort and filter memoized on their inputs. No new object or array literals in props on
  every render.
- No fetch waterfalls: the findings request starts on mount, not after another resolves.
- No virtualization library — 21 rows does not warrant a dependency.
- Respect `prefers-reduced-motion`. Motion only in response to a user action (expand,
  confirm, rerun). No entrance animations on cards or sections.

## Accessibility floor
Visible keyboard focus on every control. Table is real semantic `<table>` with `<th scope>`.
Tier is never communicated by colour alone — always colour plus the T0–T3 label.
Contrast ≥4.5:1 for text. Responsive to 768px.

## Dependencies
At most one new dev-time dependency: `@fontsource/public-sans` and `@fontsource/ibm-plex-mono`
count as one decision. Record cost in DECISIONS.md. No UI kit, no animation library,
no charting library, no icon pack beyond what is already installed.
