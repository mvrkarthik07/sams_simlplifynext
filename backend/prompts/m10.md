# M10 — Frontend transport: replace the in-memory mock with the real API client

## Objective

The SPA at `frontend/` currently uses an in-memory mock in `frontend/src/lib/api.ts` and
makes zero network calls. Make the dashboard load real data from the deployed backend over
HTTP, without changing any component, route, or state container.

## PRD justification (required by the §6.3 blocker)

PRD §7 step 2 requires the dashboard to populate with findings produced by the drift engine.
An in-memory mock cannot demonstrate that. This is the scoped exception recorded in
DECISIONS.md by the owner.

## In scope — these files ONLY

- `frontend/src/lib/api.ts`
- `frontend/src/lib/types.ts` (only if a type must widen to match the wire schema)
- `frontend/.env.example`, `frontend/.env.development`
- `backend/src/deadbolt/handlers/` — HTTP surface, CORS, error envelopes
- `backend/infra/` — CORS config on the API Function URL, if required
- `GNUmakefile` — new `gate-m10` target
- `backend/tests/integration/test_api_contract.py` — new

## Out of scope — do not touch

Any component, hook, router, store, or stylesheet under `frontend/src/`. Any protected path
(`backend/Makefile`, `backend/.github/workflows/**`, `backend/tests/gates/**`,
`backend/src/deadbolt/contracts/**`, the guard scripts). Authentication. Live provider
credentials. Schedule enablement.

## Constraints

1. The eight exported operations keep byte-identical signatures and return types:
   `getFindings`, `getFinding`, `getPlan`, `getAuditLog`, `getMetrics`, `decideApproval`,
   `rerunDriftEngine`, `executeRollback`. If the backend response shape differs from what a
   component expects, adapt inside `api.ts` — never in the component.
2. Base URL comes from `import.meta.env.VITE_API_BASE`. Default to the deployed value in
   `.env.development`. No hardcoded URL in `api.ts`.
3. Keep the mock. `VITE_USE_MOCK=1` selects it. The module exports the same surface either
   way, chosen once at module init. This is the demo fallback if the network fails on stage.
4. Every call: 8s timeout via `AbortController`, one retry on network error only (never on
   4xx/5xx), typed error objects. No silent catch, no `any` without a justification comment.
5. Backend responses use a stable envelope: `{"data": ..., "error": null}` /
   `{"data": null, "error": {"code": str, "message": str}}`. Error messages never contain
   credentials, tokens, or `raw` payload contents.
6. CORS on the API Function URL must allow the S3 website origin, methods GET/POST/OPTIONS,
   and `content-type`. **Verify this with a real preflight before writing client code** —
   if it requires a CDK change, make it in `backend/infra/` and note the redeploy in
   DECISIONS.md.
7. Read-only endpoints stay read-only. `decideApproval` / `executeRollback` may operate on
   fixture state only; they must not reach a real provider in this milestone.

## Acceptance gate

Add to `GNUmakefile`:
```bash
gate-m10:
	cd backend && $(MAKE) verify
	cd backend && uv run pytest -q -m m10 tests/integration/test_api_contract.py
	cd backend && ./scripts/guard_protected.sh
	cd frontend && npm run lint && npm run typecheck && npm run build
```

`make gate-m10` exits 0. The integration test asserts every one of the eight operations has a
backend route, that responses validate against the exported contract schemas in
`backend/artifacts/schema`, and that the error envelope is well-formed on a 404.
