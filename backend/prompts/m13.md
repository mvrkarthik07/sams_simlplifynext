# M13 — Submission packaging

## Objective
A stranger with the repo URL understands what this is, what is real, and how to run it, in
under five minutes.

## In scope
- Root `README.md` — full rewrite
- `backend/docs/DEMO_RUNBOOK.md` — new
- `backend/docs/ARCHITECTURE.md` — new, one diagram + the determinism boundary
- `GNUmakefile` — `make demo-run` verified end to end

## Required README sections, in this order
1. One sentence: what Deadbolt does and for whom.
2. Live links: dashboard, API base, MCP endpoint. State plainly that they are fixture-and-
   capture-backed, unauthenticated, and hold no customer data.
3. **What is real** — a table: system / read / revoke / rollback / data source
   (live-captured vs fixture) / why. No overclaiming. Salesforce, GHE, Workday and Notion are
   listed honestly as not credentialed.
4. The determinism claim, with the exact command that reproduces identical plan hashes.
5. 90-second local quickstart: clone, `uv sync`, `make demo-run`, open the URL.
6. Live AWS rehearsal instructions, with the throwaway-IAM-user warning intact.
7. Architecture diagram + the LLM-authored / deterministic split.
8. Cost posture: what is deployed, why it is near-zero idle, what is deliberately absent
   (no NAT, no ALB, no EC2/RDS, no OpenSearch, no SageMaker endpoint, no provisioned capacity).
9. Test and gate commands, with the current passing count and coverage.

## Constraints
- Every command in the README is executed by the agent before it is written. A command that
  was not run does not go in.
- No screenshots containing tokens, account IDs beyond the already-public stack outputs, or
  terminal history.
- No claim that is not backed by a passing test or a command in the file.
