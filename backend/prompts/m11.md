# M11 — Real GitHub data in the dashboard via a captured snapshot

## Objective
Replace simulated GitHub rows with entitlements captured from a real GitHub organisation,
without placing any credential in the deployed Lambda.

## Approach — decided, do not redesign
The real read-only GitHub provider already works locally
(`uv run python -m deadbolt.cli --system github --github-org "$GITHUB_ORG" --dry-run snapshot`).
Add a capture command that writes its normalized output to a committed artifact, and a loader
that serves that artifact as a first-class dataset alongside the fixtures. The deployed API
reads the artifact. It never holds a PAT and never calls GitHub.

## In scope
- `backend/src/deadbolt/cli.py` — new `capture` subcommand
- `backend/src/deadbolt/graph/capture.py` — new: snapshot -> redacted, canonical artifact
- `backend/src/deadbolt/providers/registry.py` — register a `captured` dataset source
- `backend/artifacts/captures/` — the committed capture + its manifest
- `backend/tests/unit/test_capture.py`, `backend/tests/integration/test_captured_dataset.py`
- `GNUmakefile` — `gate-m11`, `capture-github`

## Out of scope
Live GitHub calls from any deployed component. Storing `GITHUB_TOKEN` in CDK parameters,
Lambda environment, SSM, source, or the frontend. GitHub Enterprise, Salesforce, Workday,
Notion. Any write to GitHub.

## Constraints
1. **Redaction is mandatory and tested.** The capture writer strips: token values, `raw`
   payload bodies, email addresses (hash to a stable pseudonym), avatar URLs, and any header
   material. A unit test greps the produced artifact for `ghp_`, `github_pat_`, `Bearer `,
   `@`, and `Authorization` and fails on a hit. Repo names, org name, login handles,
   permission levels, and timestamps are retained — those are the point.
2. The artifact is canonical JSON per §2 (sorted keys, `,`/`:` separators, second-precision
   UTC) so the capture itself is diffable and hashable. Manifest records `captured_at`,
   `org`, `provider_version`, record count, and `sha256` of the body.
3. Captured entitlements carry `source="captured"` and `captured_at`. Fixture records carry
   `source="fixture"`. The engine treats them identically — this is a provenance field only,
   and it must not enter `plan_hash` or any scoring input.
4. Determinism is unchanged: given the same capture and the same `evaluated_at`, the plan hash
   is identical. Add a test asserting this against the committed capture.
5. GitHub free orgs expose no per-collaborator last-access field. Derive dormancy from the
   Events API (last commit/PR activity) and set `last_used_at=None` where no evidence exists,
   which scores as fully dormant by the existing rule. Do not fabricate a timestamp. Record
   this limitation in DECISIONS.md.
6. `capture-github` reads `GITHUB_ORG` and `GITHUB_TOKEN` from the environment, never from a
   file, never echoing either. It refuses to run if the token is passed as a CLI argument.

## Acceptance gate
    gate-m11:
    	cd backend && $(MAKE) verify
    	cd backend && uv run pytest -q -m m11
    	cd backend && uv run pytest -q -k "determinism or golden"
    	cd backend && ./scripts/guard_protected.sh

Plus: the deployed API serves at least one finding whose `source == "captured"` and whose
`system == "github"`, and coverage stays ≥85%.
