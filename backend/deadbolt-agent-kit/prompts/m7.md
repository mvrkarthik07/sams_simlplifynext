# M7 — Audit and telemetry

## Objective
Every decision, including declined ones, leaves an immutable record and a trace. This is metric
G6 and it is what a security reviewer asks for first.

## Deliverables
1. `audit/writer.py` — append-only records to S3 with Object Lock.
   - Governance mode for the sandbox; the code takes the mode from config and `README.md`
     states that production uses compliance mode. Do not hardcode.
   - Record schema: `event_id`, `ts`, `actor` (`system` | approver identity), `action`,
     `identity_id`, `system`, `resource`, `scope`, `plan_hash`, `finding_id`, `tier`,
     `decision`, `trace_id`, `pre_image_key`, `result`. Canonically encoded, hash-chained:
     each record carries `prev_hash`, forming a tamper-evident chain per plan.
   - `verify_chain(plan_id) -> bool` plus a test that mutating any record breaks verification.
   - `T0` observe-only findings also produce records. Assert this explicitly.
2. `audit/otel.py` — ADOT Lambda layer wiring, OTLP to CloudWatch.
   - One span per pipeline stage: `snapshot`, `detect`, `plan`, `broker.wait`, `execute`,
     `rollback`. Span attributes carry `plan_hash`, `finding_id`, `tier`, `provider`.
   - `trace_id` propagates from EventBridge through Step Functions into Lambda; test the
     propagation with an in-memory span exporter and assert a single trace across stages.
   - Never place secrets, PAT values, or `raw` payloads in span attributes — add a redaction
     span processor with a test.
3. Log retention set to 1 day in every log group (cost).
