# M8 — Seeded scenario and end-to-end determinism

## Objective
The demo, reproducible from a single command, plus the metric evidence the pitch cites.

## Deliverables
1. `scenarios/priya.py` + `tests/fixtures/scenario/` — one mover, one leaver, **20 planted drift
   findings** across the six systems, with a manifest declaring which 20 are expected. The
   scenario seeds real entities where the provider is real (sandbox IAM user, throwaway GitHub
   repo) and fixture entities elsewhere.
2. `make demo-reset` and `make demo-run` — idempotent seed and full pipeline execution.
3. `tests/e2e/test_full_cycle.py` marked `e2e` and `m8`:
   - Recall: detected ⊇ 19 of the 20 planted findings ⇒ metric M1 ≥ 95%. Assert on the count
     and print the miss list.
   - False revocation: zero actions executed against any entitlement present in the ratified
     template ⇒ metric M2 = 0. Assert as a hard equality.
   - Reversibility: every executed action has a verified successful rollback ⇒ metric M5 = 100%.
   - Determinism: run the full pipeline twice with the same `evaluated_at`, assert identical
     `plan_hash` and differing `plan_id`. This is the on-stage moment; it must be a test, not a
     demo trick.
4. `scripts/metrics.py` — emits M1/M2/M3/M5 as a table to stdout and a JSON artifact. Wire it
   into the e2e test so the numbers in the pitch deck come from a test run, not a claim.
5. `budget_guard/handler.py` — 6-hourly EventBridge schedule, Cost Explorer query, Slack post at
   $5 / $10 / $14 thresholds, with a `moto`-backed test. Ship this even though it is
   infrastructure: it protects the whole project.
6. `README.md`: architecture diagram reference, run instructions, the Tier A / Tier B disclosure
   in one paragraph, and the exact live-demo rehearsal checklist.

## Gate
`make gate-m8`
