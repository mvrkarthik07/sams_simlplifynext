# M4 — Executor: idempotency, dry-run, verify, rollback

## Objective
The invariant chain from PRD §4.8, implemented so that M5 (Reversibility, 100%) is structural
rather than aspirational. Built and proven entirely against fixture providers and `moto`.

## Deliverables
1. `executor/idempotency.py`
   - Lock key: `sha256(f"{plan_id}|{seq}|{resource}|{scope}")`.
   - DynamoDB conditional write `attribute_not_exists(PK)` with a TTL. A duplicate delivery is
     a no-op returning the original `ActionResult`, not a second mutation.
   - Test: invoke the same action 50 times concurrently (threads) and assert exactly one
     provider mutation.
2. `executor/run.py` — strictly ordered, fail-closed:
   1. acquire idempotency lock
   2. capture pre-image via provider read; write to versioned S3; **no pre-image ⇒ raise
      `IrreversibleActionError` and do not proceed**
   3. `revoke(dry_run=True)`; a failing dry run aborts before any mutation
   4. `revoke(dry_run=False)`
   5. verify by re-reading the live entitlement and asserting the expected post-state; a failed
      verification triggers automatic rollback and surfaces `ok=False`
   6. write the audit record
   - Every step emits a structured log line with `plan_hash`, `seq`, `trace_id` — never the
     `raw` payload.
3. `executor/rollback.py` — `rollback(plan_id, seq | all)` reads the pre-image, calls
   `restore`, verifies, and writes a linked audit record referencing the forward action.
4. Tests marked `m4` and `rollback`, ≥95% coverage of `executor/`:
   - Property test: for every fixture entitlement, `execute` then `rollback` returns the
     provider to a state deep-equal to the pre-execution snapshot. This is metric M5.
   - Failure injection at each of the six steps; assert the invariant that a failure after
     step 4 always leaves either a completed action or a completed rollback, never neither.
   - Dry run performs zero mutations (assert via provider mutation counter).
   - Missing pre-image raises and executes nothing.

## Gate
`make gate-m4`
