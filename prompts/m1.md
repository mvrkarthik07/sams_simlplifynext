# M1 — Fixture providers + entitlement graph store

## Objective
Two Tier-B providers and the graph persistence layer, both fully exercised without touching a
real API. This proves the interface is swappable before any real connector is written.

## Deliverables
1. `providers/fixtures/salesforce.py`, `providers/fixtures/workday.py` — implement
   `EntitlementProvider` against deterministic seed data in `tests/fixtures/seed/*.json`.
   - `snapshot()` returns a stable, sorted iterable. Same seed ⇒ same order, always.
   - `revoke(dry_run=True)` mutates nothing and returns a populated `pre_image`.
   - `revoke(dry_run=False)` mutates only in-memory state and is idempotent on repeat.
   - `restore(pre_image)` returns state to the exact pre-image; assert deep equality.
2. `providers/registry.py` — builds the provider set from a config mapping
   `{"salesforce": "fixture", "aws-iam": "real", ...}`. Swapping a value must change nothing
   outside this module. Add `test_registry_swap_is_config_only` proving the engine imports
   no provider module directly.
3. `graph/store.py` — DynamoDB single-table repository, exactly the key design in PRD §4.4
   including `GSI1 (RES#{system}#{resource} / ID#{identity_id})`.
   - `put_entitlements`, `get_identity_entitlements`, `who_can_reach(system, resource)`,
     `put_identity`, `get_role_template(title_slug, version)`, `put_finding`, `put_plan`
   - Batched writes with `BatchWriteItem` and unprocessed-item retry with capped backoff.
   - All access goes through this module; no other module constructs a DynamoDB client.
4. `graph/snapshot.py` — fan-out across providers, normalize identities by lowercased email,
   write current state to DynamoDB and a point-in-time snapshot to S3 at
   `snapshots/{iso_hour}/{system}.json` using the canonical encoder (M3 will own the encoder;
   for now put a minimal `canonical_dumps` in `plan/canonical.py` and reuse it).
   - Provider failure is isolated: one failing provider marks that system `stale` in the run
     record and does not abort the others. Add a test for partial failure.
5. Tests marked `m1` using `moto` for DynamoDB and S3. Run
   `assert_provider_contract` from M0 against both fixture providers.

## Gate
`make gate-m1`  (≥95% coverage on `contracts/` and `providers/fixtures/`)
